2C. Boundary Sistem: Laptop vs Vercel

Ini rules tetap supaya architecture tidak bercampur: laptop ialah executor, Vercel ialah monitor, dan normal runtime mesti fully automation.

Laptop Windows 24 Jam

  • Bot berjalan 24 jam di laptop.
  • Bot ambil price dan candle dari MT5.
  • Bot ambil chart screenshot secara automation dan hantar market context kepada AI.
  • AI pulangkan keputusan BUY, SELL, atau HOLD.
  • Bot execute trade di MT5 jika AI + risk filter lulus.
  • Bot update heartbeat, active trade, pattern usage, dan trade events ke Supabase.

Vercel Server / Website

  • Vercel tidak connect MT5.
  • Vercel tidak buka atau close trade.
  • Website hanya baca database Supabase guna anon key.
  • Dashboard tunjuk heartbeat, active trades, virtual SL/TP, pattern usage, dan timeline.
  • Kalau laptop offline, Vercel masih online tetapi data akan jadi stale/manual mode.
FINAL RESPONSIBILITY SPLIT
Laptop 24 jam:
price + screenshot automation -> AI info -> MT5 trade -> Supabase database update

Vercel server:
Supabase database read -> website dashboard info -> user pantau

3. Active Trade Management

Requirement baru: setiap trade yang sedang berjalan mesti dikawal sampai trade itu tamat, dengan virtual SL/TP dan virtual trailing stop dalam sistem, bukan diletakkan dalam MT5.

ACTIVE TRADE MANAGER
  |
  v
Get all open positions from MT5
  |
  v
For each ticket individually
  |
  +-- Ticket 1001: analyze current price, profit, drawdown, original pattern, trend
  +-- Ticket 1002: analyze current price, profit, drawdown, original pattern, trend
  +-- Ticket 1003: analyze current price, profit, drawdown, original pattern, trend
  +-- Ticket 1004: analyze current price, profit, drawdown, original pattern, trend
  |
  v
Decision per trade
  |
  +-- HOLD: thesis still valid
  +-- PROTECT: update hidden/virtual stop level in bot memory
  +-- TRAIL: move hidden virtual trailing stop by ATR / structure / liquidity
  +-- TAKE PROFIT: close ticket when virtual TP condition is hit
  +-- CUT LOSS: close ticket when virtual SL condition is hit
  +-- TRAILING STOP HIT: close ticket when virtual trail is touched
  +-- EXIT: close ticket if thesis invalid
  |
  v
Bot sends close order to MT5 when virtual trigger is hit
  |
  v
Save virtual SL/TP, decision, and result into trade memory + log
Per Ticket

Satu trade, satu keputusan

Kalau ada 4 trade aktif, bot tidak anggap semuanya sama. Setiap ticket dinilai berasingan ikut entry, profit, drawdown, trend, pattern, dan sebab asal trade dibuka.

Dynamic Exit

Virtual SL/TP dalam bot

SL dan TP tidak dihantar sebagai fixed level kepada broker. Bot simpan hidden level dalam memory dan trigger close sendiri bila price sampai condition.

Virtual Trail

Dynamic trailing stop tersembunyi

Trailing stop juga tidak diletakkan dalam MT5. Bot kira trailing level sendiri ikut ATR, swing structure, liquidity, profit lock, dan current volatility.

Pattern Identity

Trade ingat pattern asal

Setiap ticket simpan primary_pattern, semua pattern confluence, timeframe, confidence, dan sebab asal entry supaya dashboard boleh tunjuk trade itu dibuka berdasarkan pattern apa.

Fail-safe

Risiko virtual exit

Jika laptop, internet, MT5, atau API mati, virtual SL/TP/trailing stop tidak boleh trigger. Jadi sistem perlu watchdog/kill switch, bukan sekadar harap bot hidup.

Prinsip baru: bot bukan sekadar buka trade. Selepas trade dibuka, bot menjadi trade manager yang menjaga setiap position sampai selesai. SL/TP tidak diletakkan sebagai broker-side fixed target; trailing stop juga tidak diubah dalam MT5. Semua level exit menjadi virtual trigger dalam sistem. Bila condition kena, bot sendiri hantar arahan close ticket ke MT5.

5. AI Cloud Architecture

Dalam planning terbaru, AI tidak lagi perlu berjalan di laptop. Laptop hanya panggil API dan tunggu jawapan penuh.

Main AI

Market signal

Tugas utama ialah baca market context, indicator, pattern, trend, session, dan bagi output JSON:

  • BUY
  • SELL
  • HOLD
Risk AI

Second opinion

Hanya dipanggil bila main AI beri signal valid. Tugasnya approve atau reject trade berdasarkan risk/reward.

Safety

No JSON, no trade

Kalau AI timeout, API down, atau response bukan JSON valid, bot tidak boleh buka trade.

Rule penting: AI call mesti blocking dan sequential. Main AI mesti siap dahulu sebelum Risk AI. Risk AI mesti siap dahulu sebelum order dihantar ke MT5.

11. One-Year Backtest Duplicate Guard

Supaya kalau run_yearly_backtest.bat tertekan dua atau tiga kali, result tidak duplicate dan file tidak berebut ditulis.

RUN YEARLY BACKTEST
  |
  v
Read state: TESTING DATA SETAHUN/storage/backtests/yearly_backtest_state.json
  |
  v
Read live coverage: TESTING DATA SETAHUN/storage/live/live_data_state.json
  |
  +-- no previous baseline
  |       |
  |       v
  |   Run full year:
  |   today - 1 year  ->  today
  |
  +-- previous baseline exists + live data covers today
  |       |
  |       v
  |   Normal run = 0 historical days
  |   because live 24h bot already covered realtime data
  |
  +-- previous baseline exists + bot was offline too long
          |
          v
      Continue from last tested/live-data date
      example: 2026-05-25 -> 2026-06-20
  |
  v
Create lock file: TESTING DATA SETAHUN/storage/backtests/yearly_backtest.lock
  |
  +-- lock already exists
  |       |
  |       v
  |   STOP second run
  |   Show: Yearly backtest already running
  |
  v
Run collect history + simulate trades + pattern analytics
  |
  v
Write CSV/report by replace, not append
  |
  v
Save latest completed date into yearly_backtest_state.json
  |
  v
Remove lock file after finish
Kalau laptop crash dan lock tertinggal, run command ini sekali sahaja: cd "TESTING DATA SETAHUN" kemudian python run_yearly_backtest.py --force-unlock. Normalnya awak cuma tekan TESTING DATA SETAHUN/run_yearly_backtest.bat; duplicate guard akan protect secara automatik. Kalau mahu test gap dari last baseline ke hari ini, guna python run_yearly_backtest.py --include-gap. Kalau mahu paksa full year semula, guna python run_yearly_backtest.py --full-year. Kalau mahu skip gap walaupun lama tidak buka, guna python run_yearly_backtest.py --skip-gap.
